Setting up a proper development environment was one of my first milestones. Here's what I use daily and why each tool earned its place.

## Code Editor: VS Code

Visual Studio Code is my primary editor. As a beginner, these features matter most:

- **IntelliSense** — Auto-completion that helps me learn API surfaces
- **Integrated terminal** — No switching between windows
- **Extension ecosystem** — Tailwind CSS IntelliSense, Astro language support, etc.
- **Git integration** — Visual diffs and staging right in the editor

### Essential Extensions

- **Astro** — Syntax highlighting and language support for `.astro` files
- **Tailwind CSS IntelliSense** — Autocomplete for utility classes
- **ESLint** — Catches errors before I run the code
- **Prettier** — Consistent formatting without thinking about it

## Terminal: WSL (Windows Subsystem for Linux)

I run WSL on Windows, which gives me a full Linux terminal. This matters because:

- Most development tutorials assume a Unix-like environment
- Node.js and Git work more reliably on Linux
- I'm learning terminal commands that transfer to any server

## AI Assistant: Claude Code

Claude Code is my primary vibe coding tool. My workflow with it:

1. Describe what I want to build
2. Review the generated code carefully
3. Ask "why" questions about anything I don't understand
4. Iterate until I'm happy with both the code and my understanding

The key is treating it as a tutor, not a crutch. I never ship code I can't explain.

## Notes & Knowledge: Obsidian

Obsidian is where I keep my learning notes. My system:

- **Daily notes** — What I learned, what confused me, what clicked
- **Project notes** — Plans and decisions for each project
- **Concept notes** — Explanations of concepts I've learned (in my own words)
- **Links between notes** — Connecting related concepts builds understanding

## Version Control: Git & GitHub

Every project lives on GitHub. My Git workflow as a beginner:

```bash
# Start working
git checkout -b feature/new-thing

# Make changes, commit often with descriptive messages
git add specific-file.ts
git commit -m "Add navigation component with mobile menu"

# Push and create PR when ready
git push -u origin feature/new-thing
```

Descriptive commit messages are part of my learning documentation.

### The "3 Things" Rule
Each day, I pick three things to focus on. No more. This prevents the scattered "I started 5 tutorials and finished none" trap.

### Learning Log
I keep a simple log of what I learn each day. It's not fancy — just a few bullet points. But looking back at a month of entries shows real progress.

### Project-Based Learning
Every new concept gets applied to a real project. I don't just read about CSS Grid — I use it to build the projects page layout.

- **Testing framework** — Jest or Vitest for automated tests
- **CI/CD** — Automated builds and deploys on push
- **Docker** — Containerized development environments

I'll add these as my projects demand them, not before.
