## The Spark

Everyone has a moment where they decide to learn to code. For me, it was the realization that I had ideas I couldn't build. I'd see a problem, imagine a solution, and then... nothing. I didn't have the skills to make it real.

I tried the traditional route — online courses, tutorials, "learn X in 30 days" promises. I'd get through the basics, build a todo app, and then hit a wall. The gap between tutorial exercises and real projects felt enormous.

## Discovering Vibe Coding

Then I discovered a different approach. Instead of spending months learning theory before building anything meaningful, what if I could:

1. **Describe** what I wanted to build in plain English
2. **Generate** working code with AI assistance
3. **Study** every line to understand how it works
4. **Iterate** and make it my own

This is vibe coding — and it flipped my learning on its head.

## Why This Works For Me

{/* TODO: Personalize these reasons */}

Traditional learning goes: **theory → practice → build.**
Vibe coding goes: **build → study → understand.**

When I see working code that does exactly what I described, I can trace the logic, ask "why was it done this way?", and learn from real, functional examples instead of abstract exercises.

It's like having a patient tutor who:
- Never gets frustrated with my questions
- Can show me multiple ways to solve a problem
- Explains things at whatever level I need
- Is available at 2am when I'm in the zone

## The Plan

Here's what I'm committing to:

- **Build at least one project per month** — real things, not just exercises
- **Document everything** — this blog is my public learning journal
- **Be honest about my level** — no fake expertise, no inflated skill bars
- **Study every line** — vibe coding isn't about blindly copying, it's about understanding

## What's Next

My first real project is this portfolio website. I described every detail — the design, the pages, the functionality — and worked with Claude Code to bring it to life. The next post will break down exactly how that process worked and what I learned.

If you're reading this and thinking about learning to code — whatever your approach, just start building. The best way to learn is to make things.
